# Robot Catalog

Product specs for mobile robots of all kinds — AMRs, AGVs, humanoids, quadrupeds, wheel-legged robots, indoor and outdoor delivery robots, and development platforms — with a page per robot, a dashboard and a mega table.

**Live site:** https://htcrefactor.github.io/robot-catalog/

## Layout
- `data/parts/*.json` — source of truth, one file per category, one record per robot (see `data/SCHEMA.md`)
- `data/robots.json` — merged file the site reads (`python scripts/merge.py`)
- `data/fx.json` — KRW cross rates and their ECB reference date, for the KRW figures (`python scripts/build_fx.py`)
- `index.html` (all robots) · `robot.html?id=…` (one robot) · `dashboard.html` (charts) · `table.html` (mega table)
- `research/disagreements.json` + `review.html` — maintainer-only cross-catalogue review aid (below)
- `data/robots.csv` — the same records, one row per robot, written by the same `merge.py`
- `index.html` (all robots) · `robot.html?id=…` (one robot) · `dashboard.html` (charts) · `table.html` (mega table) · `specs.html` (every spec field) · `data.html` (open data)

## Open data
- **Download page:** https://htcrefactor.github.io/robot-catalog/data.html — the files, every field with its unit, the license, the version and example fetch code.
- `data/robots.csv` (35 columns, UTF-8, one row per robot, sorted by `id`) and `data/robots.json` (`meta` + records) are both generated by `python3 scripts/merge.py`; `scripts/validate.py` fails if the committed CSV no longer matches `data/parts/`.
- **License:** the data is CC BY 4.0 — see `DATA-LICENSE.md`. The site's HTML/CSS/JS is not covered by that license. Third-party values keep their own credit (HumanoidStore open data, CC BY 4.0 — see the `data_source` field).
- `llms.txt` (index for LLM agents) · `llms-full.txt` (whole catalog in one file) · `md/<id>.md` (one robot per file, full spec sheet with a source on every value) — generated by `python scripts/build_llms.py` from `data/robots.json` and `data/specs/*.json`

## Data rules
Every number comes from a manufacturer page, datasheet or manual listed in that record's `sources`, except where noted below. Unknown values are `null` and show as "—" or "N/S" (not stated). Nothing is guessed.

Humanoid prices, delivered prices to the US and Germany, sales status, FCC IDs and public tender prices come from HumanoidStore's open data (https://humanoidstore.co/data, dataset dated 2026-11-04, CC BY 4.0, credit "HumanoidStore (humanoidstore.co)"). 107 humanoids whose only source so far is that dataset carry `"data_source": "HumanoidStore open data (CC BY 4.0)"`; their specs are as HumanoidStore states them, not yet checked against the makers' own pages.

## Cross-catalogue disagreements (maintainers only)
For every record that carries `seen_on` (the competitor catalogues we know list it), `scripts/build_disagreements.py` opens that catalogue's page for the model and compares what it publishes with the value in `data/parts/*.json`.

- `research/disagreements.json` — one entry per robot: the values that differ and the fields we leave empty, each with the catalogue page and the maker source the catalogue cites.
- `review.html` — the review page. Hidden: `noindex`, no menu link, not in `sitemap.xml`.
- Rebuild: `docker`-free, stdlib only — `python3 scripts/build_disagreements.py` (pages are cached in `.cache/disagreements/`, so a rerun only fetches what is missing; `--offline` rebuilds from the cache).

A competitor figure is a pointer to the maker's own document, never a value for the data: nothing in `data/parts` or `data/specs` may be filled from a competitor or aggregator, and this script writes only `research/disagreements.json`.

## Prices
A price is stored as a dated observation (`price_observations`): the amount in the currency the maker states, the date it was checked, the kind of price, and the maker or official-store URL — never a competitor, reseller or aggregator. A record can carry several, one per date or variant, and the robot page draws them as a price history.

KRW is not stored anywhere. `data/fx.json` holds KRW per 1 unit for 30 currencies crossed from the European Central Bank's daily reference rates, with the ECB's reference date, and the pages convert at display time so the rate and its date stay next to the figure (`python3 scripts/build_fx.py` refreshes it). A price recorded before dated observations were introduced has no date, so it is shown as stated and **not** converted; those are the only records that still use `price_usd` / `price_note`.

## Safety & certifications
AMR, AGV, delivery and mobile-platform records carry the safety profile their maker states: `safety_standards` (e.g. ISO 3691-4, EN ISO 13849-1), `certifications` (CE, UL 3100, FCC, KC, KIRIA …), `safety_pl` (PL d, SIL 2), a `safety_note` for exclusions or an explicit absence of certification, and the maker URL that states them in `safety_source` (see `data/SCHEMA.md`). The robot list and mega table filter on them and the robot page shows them next to the IP rating. The payload class (≤50 / 50–200 / 200–500 / 500–1500 / >1500 kg) is a display band derived from `payload_kg`, not a stored field.

## Theme and languages
- Light/dark toggle (🌙/☀️) in the header; follows the system setting until changed, then remembered.
- UI in English and Korean (EN/KR switch). Strings live in `assets/i18n.js`: add a language by adding a block with the same keys and listing it in `LANGS`. Category/status/country values are translated via `VALUE_KO`. Robot summaries stay in English unless a record has `summary_ko`.
- Korean-market data (Issue #35): `name_ko` (official Korean product name), `manufacturer_ko` and `kr_distributors` (Korean sales channels: maker direct, official distributor or reseller) are set from the maker's Korean page or an official Korean distributor's page. Where they are present the UI shows the Korean name next to the English one, and the robot page lists the Korean sales channels with a Korean-market note.
